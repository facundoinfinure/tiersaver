What a simulation shows

  • How many profiles were evaluated, how many would be suppressed, how many are kept and how many were skipped.
  • For kept profiles, the reason. A profile can be kept for several reasons at once.
  • A sample of the candidates, so you can check them before you approve.
  • How many active profiles you would have afterwards.

A simulation changes nothing in Klaviyo.

Approving

When you approve a simulation, TierSaver suppresses exactly the profiles in that simulation and no others. Before it sends each batch to Klaviyo it leaves out any profile that should no longer be suppressed.

An approval is tied to one simulation:

  • It expires after {{sim.ttlHours}} hours. Lists change. If more time has passed, you get a fresh simulation to review.
  • It runs once. A simulation cannot be used for a second cleanup.
  • Changing your criteria replaces it. If you edit the cleanup criteria or a protected list, pending simulations are discarded.

The app records who approved each simulation, when, and under which criteria.

The first cleanup is always manual

You start the first cleanup yourself, after reviewing its simulation. Monthly cleanups only start after that.

Monthly cleanups

Before each monthly cleanup TierSaver runs a new simulation and emails you a summary. There are two modes:

  • Approval required (default). The cleanup waits for you to approve the simulation.
  • Automatic. An explicit opt-in. The cleanup runs on the scheduled day using the new simulation, and you still receive the summary.

See the monthly schedule for when cleanups run.

What to know before you approve

  • Suppressed profiles can no longer receive marketing email from you, even if they later buy.
  • If you remove a suppression, Klaviyo does not let that profile be suppressed again for {{klaviyo.resuppressDays}} days from the previous suppression.
  • Your Klaviyo plan does not change automatically unless you enabled auto-downgrade in Klaviyo.

While a cleanup runs

Profiles are suppressed in batches. The app shows the state of the run: queued, running, completed, or completed with errors. If a run is interrupted, it resumes where it stopped without suppressing anyone twice or skipping a batch. If a batch keeps failing, the run stops and the remaining profiles are left untouched.
